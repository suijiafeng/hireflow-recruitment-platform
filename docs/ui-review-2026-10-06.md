# UI 合理度走查：展示、交互、浏览器适配（2026-10-06）

走查方式：以 HR 登录，逐页在 1440、1280、1024、375 四种宽度下截图对比；弹窗、抽屉、通知面板在 375 下用脚本量实际位置；键盘 Tab 逐项检查焦点可见性；对照 CSS 断点与构建配置看浏览器兼容。

结论先说：**桌面端（≥1280）展示与交互成熟，没有明显问题；1024 可用但有挤压；375 手机宽度的后台页面只做了头部适配，内容区基本不可用。** 候选人 / 新员工门户是另一套手机优先的布局，之前已验证正常。

严重度：**P1** 看不到或用不了 · **P2** 挤压、误导 · **P3** 打磨

---

## P1 手机宽度（375）后台页面

后台按设计是桌面优先，但 HR 和用人经理在手机上看一眼待办、审批一个 Offer 是真实场景。目前这些页面在 375 下的状态：

1. **侧边栏占 64px 固定不收。** 内容区只剩 311px。手机上应改成汉堡按钮 + 抽屉式菜单。
2. **面试管理：列表整个消失，只剩「我的可约时段」。** 右栏 `.hf-rail` 固定 400px，没有窄屏规则，把主列表挤出可视区。这是 10 个页面里唯一完全不可用的。
3. **数据大盘：图表卡片标题竖排成一字一行**（「招聘漏斗」「AI 健康度诊断」），漏斗条形图没有宽度，KPI 五张卡横向溢出，待办数字一排挤在一起看不出哪个是哪个。
4. **通知面板超出屏幕。** 弹层宽 375 但从 x=−76 开始，左侧 76px 被裁掉，每条通知的开头看不到（「…已完成：周一鸣」）。
5. **候选人详情抽屉头部重叠。** 抽屉已铺满宽度，但姓名被挤出左边界、邮箱截断、「加入职位」「导入简历」与关闭按钮叠在一起，Tab 栏的「应聘记录」被挡住。
6. **录用管理、入职管理：KPI 卡片文字缩写成「待..」「本..」**，数字和单位溢出；表格只剩「候选人 + 操作」两列，看不到状态，审批需要横向滚动才能找到按钮。

## P2 1024 宽度与通用

7. **1024 下大盘待办行被截断**：最后一项「材料待人工核…」切掉，没有换行或滚动提示。
8. **看板横向滚动没有提示**：1024 下「已入职」列在视区外，列头没有阴影或箭头提示还有列。
9. **面试管理对 HR 常驻「我的可约时段」栏**：HR 带有提交面评权限所以显示，但大多数 HR 不做面试官；该栏占 1/3 宽度，内容是解释文字。建议只在本人有被指派面试或主动开启时显示。
10. **大盘默认选中的职位不是最新的**：清库后新建「测试开发工程师」，大盘仍默认「产品经理（B端）」。按「最近有动态」排序更符合预期。
11. **通知面板宽度固定**，在 1024 下也贴着右边缘；跟随视口宽度更稳。

## P3 打磨与兼容

12. **键盘焦点只有浏览器默认 1px 细线**：`.hf-link` 等可点元素 Tab 到时能看到焦点，但很细；建议统一用 2px 的 `:focus-visible` 外框，和表格行深链接高亮同一色系。
13. **CSS 动画不响应「减少动态效果」**：antd 的动效已经按系统偏好关闭（main.tsx），但自写的 `fadeInUp`、`hf-row-deeplink` 两个关键帧没有 `prefers-reduced-motion` 包裹。
14. **没有深色模式**：系统深色下页面仍是白底，不算问题，但 `color-scheme` 未声明会让滚动条、表单控件在深色系统下出现白黑混搭。
15. **滚动条样式只覆盖 WebKit**：Firefox 下表格滚动条是默认样式，功能正常。
16. **构建目标**：Vite 默认 `modules` 目标（Chrome 87+ / Safari 14+ / Firefox 78+），没有 browserslist；`text-wrap: pretty` 等新属性只是渐进增强。企业内常见的旧版 Edge / 国产浏览器兼容模式不在范围内，若有需要再加 legacy 插件。
17. **响应式断点分散**：960、767、992、1280、1366、1440 六个断点各管各的，没有统一的尺寸变量；后续做手机适配时建议收敛到 3 档。

## 验证通过的点

- 1440 / 1280：九个后台页面排版一致，KPI、表格、看板、图表都在视区内；表格操作列固定右侧；录用管理分组表头只画一次。
- 1024：侧边栏自动收成图标，悬停有名称提示；表格横向滚动；抽屉 760px 仍能完整显示。
- 375：登录页、新增候选人弹窗（自动缩到 359px）、门户页面都正常；头部已按窄屏收起面包屑和用户名。
- 交互：Esc 关弹窗与抽屉；弹窗不会被遮罩误关；Tab 可以走到所有行内操作；深链接高亮目标行。
- 页面标题随页面变化，`lang="zh-CN"`，viewport meta 正确。

## 建议顺序

1. 面试管理的右栏加窄屏规则（否则该页在手机上完全不可用）——改一条 CSS。
2. 通知面板和候选人抽屉头部在 375 下的溢出——两处局部样式。
3. 侧边栏在 <768 改为抽屉菜单；大盘、录用、入职的 KPI 在窄屏改为两列网格——这是真正的手机适配，工作量在半天到一天。
4. 其余 P2 / P3 按需。
